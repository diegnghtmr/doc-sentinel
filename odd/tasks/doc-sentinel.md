# doc-sentinel — feature document (ODD)

Parent meta-harness repo that pins third-party sub-harnesses by exact `main` SHA (git submodules) and orchestrates them in three modes: `clean`, `detect`, `update`.
Source of design truth: `PLAN.md` (13 Nov 2026). This document holds the specs, tasks and log; read it until `## Log` inclusive.

## Specs

- **S1 — Parent repo + pinned sub-harnesses.** User: "este proyecto es de repositorio y acabar de, pues estos subproyectos, que a su vez vamos a crear un supernamespace para solucionar esto". Implement PLAN §1, §4, §5.1: repo `doc-sentinel`, package `doc_sentinel`, `third_party/<id>` git submodules checked out at the exact SHAs of PLAN §5.1, `pins.lock.json` with `schema_version`, `branch_policy`, and per-pin `id,url,branch,sha,path,inspected_at`. No vendored code. Acceptance (PLAN Fase 0): "`git submodule status` muestra exactamente esos SHA; `doc-sentinel version` corre."
- **S2 — CLI.** PLAN §6 verbatim surface:
  ```
  doc-sentinel clean  <file> [--output PATH] [--json] [--report PATH]
  doc-sentinel detect <file> [--json] [--report PATH] [--allow-network]
  doc-sentinel update [--dry-run] [--only ID] [--json]
  doc-sentinel version
  ```
  Exit codes per PLAN §6 table (0/1/2 per mode). `clean` default output `<stem>.cleaned<suffix>`; aborts if destination exists unless `--force-output`, never onto the input.
- **S3 — clean mode.** PLAN §2.1 + principles 2, 6, 7, 9: only watermarks-remover CLI scripts (`inspect_file.py`, `clean_file.py`, `clean_text.py`); never `server.py` / `POST /clean` / `rewrite_text.py` / Layer B / `--in-place`. Original SHA-256 unchanged. C2PA removal/residual always logged. Report never written inside the document. Acceptance (Fase 2): "el fixture Unicode del smoke (U+202F + U+200B) se limpia sin cambiar letras visibles"; "el original conserva el mismo SHA-256".
- **S4 — detect mode.** PLAN §2.2, §7, §10, §11: read-only, offline by default (`HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`), adapters perlecta, hidden-text-detector, subtext-scan, chk_defaced (separate process only, AGPL), unicode-smuggling-guard, plus own channel extractor (filename, metadata, comments, alt, hyperlinks, embedded, form fields, tracked changes). Per L20 ("no usemos el modelo local"): the local Prompt Guard 2 model is **not used by default** — `prompt-guard` is removed from the default detect matrix and is only an explicit opt-in (`detect --prompt-guard`, never downloads). The linguistic layer is own deterministic glue `instruction-phrases` (ES+EN rules, no model, no network), justified by the demonstrated gap in L8 (subtext-scan `phrases: []` on the Spanish samples); it is mandatory for text-bearing formats. Severity: high when the matched text is hidden (revealed by a document-layer adapter) or sits in filename/metadata/comment/annotation/alt/hyperlink/embedded/form/tracked-change channels; medium when it is visible body text (a document may legitimately discuss prompt injection). Missing adapters appear in `adapters_skipped`; never pretend a layer ran.
- **S5 — Schema + deterministic aggregator.** PLAN §8, §9: normalized finding (`class`, `channel`, `severity` controlled vocabularies), run report JSON, severity mapping, dedup rule, verdicts `clean`/`findings`/`error` (detect) and `cleaned`/`already_clean`/`residual`/`error` (clean). "El agente no emite el veredicto." Aggregator calls no LLM.
- **S6 — Intent router.** PLAN §12 + Fase 1: rules-based, Spanish and English: «límpialo», «quita las marcas», *clean*; «revisa», «detecta injection», *detect* / *scan*; «actualiza», *update* / *bump pins*. Acceptance: "100 % de fixtures de intención bien clasificados".
- **S7 — update mode.** PLAN §5.2 algorithm: fetch, compare, checkout new, changelog `git log --format='%h %s' old..new` (max 30 lines), run corpus, persist or roll back **only** that pin; statuses `unchanged | updated | rolled_back | fetch_error`; `UPDATES.md` entry; exit 0/1/2. Acceptance (Fase 5): "un test de integración simula un pin roto ... y verifica el rollback de **solo** ese id; un pin bueno avanza y queda registrado."
- **S8 — Agent contracts.** `AGENTS.md` and `CLAUDE.md` with the content of PLAN §12 and §13.
- **S9 — Corpus.** PLAN §15: fixtures generated by script (no opaque binaries without recipe), `tests/corpus/manifest.yaml` with `must_find` / `must_not_find` / `visible_unchanged`; clean controls must not raise `high`/`critical`. Per L20, every corpus entry that skipped for lack of the model or for lack of a realistic fixture must be backed by a synthetic or publicly sourced example built the way the attack/trace really occurs (e.g. Word white 1 pt runs like the user's samples, the same converted to PDF, C2PA-signed media from public test fixtures fetched by pinned URL + SHA-256 into a git-ignored dir, PDFs with AI producer/XMP metadata, ToUnicode-remapped fonts, OCR-able injection images, Spanish metadata/filename injections), plus visible-discussion controls that must not raise high. Human-openable copies are also generated into `samples/synthetic/` (git-ignored) for manual experiments.
- **S10 — Experiments with the user's samples.** User: "También te puse los ejemplos ... tres documentos de Word. Dos son para la parte de inyección de prompt y la otra es para la parte de marca de agua. La idea es que experimentemos con estos para validar que funcione". `detect` on `ejemplo 1 prompt.docx` and `ejemplo 2 prompt.docx` must report the hidden AI-directed instructions (verdict `findings`); `clean` on `ejemplo 3 marca de agua.docx` must remove the AI-tool trace it carries into a new file and leave the original byte-identical. Per L6 the trace to remove is the HTML-paste residue: unreferenced `<w:div>` entries in `word/webSettings.xml` and orphan custom character styles whose names are CSS-class-like and that no part references (e.g. `o00408`, `s01997`, `first-table-reference`); visible text must stay identical. Implemented as own deterministic glue (`doc_sentinel/glue/ooxml_paste.py`) chained after watermarks-remover, justified by this sample as a demonstrated gap (PLAN principle 1). Per L10/L11, `clean` on the four new watermark samples must output copies whose post-clean inspect shows no AI metadata (creator/lastModifiedBy/description/Application/Company/custom AI props, library-default generator fingerprints such as docx-js `Un-named` and python-docx `generated by python-docx`), no C2PA in embedded media (or the residual is reported), and no invisible Unicode (U+200B/U+200D/U+202F), with visible text otherwise unchanged; originals byte-identical. Any trace WMR leaves behind is a demonstrated gap closed by own glue.
- **S11 — Containers + CI + README.** PLAN §3, §16, Fase 6: `containers/Dockerfile.detect`, `Dockerfile.clean`, `compose.yaml`; `.github/workflows/ci.yml`; README.

- **S12 — Docker distribution + Windows 11 launcher.** User (L28): "entonces vamos con docker. Genera el arnes completo y que soporte el docker desktop si detecta que esta en wind11". One image `doc-sentinel` (tag `doc-sentinel:local`, `containers/Dockerfile`) with the complete harness: all pinned sub-harnesses, chk_defaced built from the pinned submodule (separate binary, AGPL), Node ≥ 22.13 + subtext-scan deps, tesseract (spa+eng), qpdf, poppler, exiftool, c2patool (pinned release + SHA-256), Python extras `clean,detect` (no torch/Prompt Guard). `.dockerignore` must exclude user documents (`/*.docx`, `/*.xlsx`, `/*.pptx`, `/*.pdf`), `samples/`, `work/`, `.venv`, `.cache`, `bin`, caches, `tests/corpus/generated`. Container contract: `ENTRYPOINT ["doc-sentinel"]`, non-root user, `WORKDIR /work`; launchers run it with `--rm --network=none --read-only --tmpfs /tmp --cap-drop=ALL --security-opt=no-new-privileges -e DOC_SENTINEL_NO_NETNS=1`, the input file's directory bind-mounted read-only at `/work/in`, the output directory read-write at `/work/out` (and the report directory at `/work/report` when different), `--user <uid>:<gid>` on Linux. `DOC_SENTINEL_NO_NETNS=1` is honored only when the process has no non-loopback network interface (fail closed otherwise). Launchers: `scripts/doc-sentinel.ps1` (+ `scripts/doc-sentinel.cmd` shim) for Windows — detects Windows 11 (build ≥ 22000; warns on older builds), ensures Docker Desktop is installed and running in Linux-containers mode (starts `Docker Desktop.exe` and waits when it is not), builds the image when missing, maps Windows paths to the mounts, validates on the host that output/report ≠ input, and runs `clean`/`detect`/`version`/`intent`; `scripts/doc-sentinel-docker.sh` for Linux/macOS with the same contract. `update` is refused by the launchers (it needs git + network; run it from a checkout). Exit codes and stdout/stderr of the container are passed through unchanged.

- **S13 — Agent-orchestrated semantic review (no local model).** User (L30): the orchestrating agent (any: Claude Code, Codex, Antigravity, Copilot, Grok, OpenCode, …) receives only the mode and the file; it must NEVER read the document ("el orquestador no puede revisar … porque … quedaría infectado de inyección de prompt"). It runs the deterministic tool; the deterministic part decides which concrete fragments need semantic review and how many subagents (sequential or parallel); each subagent receives ONLY its fragments ("pasarle la información únicamente que obtuvimos de la parte determinista … y él … nos va a dar esa puntuación"); scores come back and the deterministic aggregator recomputes the verdict. "Lo importante es que sea muy sencillo": the user passes a file and a mode in chat and the agent knows what to do. Agent-neutral: canonical `AGENTS.md` + `CLAUDE.md` pointer + minimal per-agent wiring only where a tool needs it ("no debe estar sesgado a un solo agente"). Design (parent, from L30 + principles §1.3/§1.4/§1.5): (1) `detect --review-dir DIR` writes a review plan (task ids, batches, per-batch fragment files, plan hash) and an orchestrator-safe summary with NO document text; (2) subagent contract: read only its batch file, no other tools, answer only JSON `{task_id, label ∈ {injection, benign, unsure}, score ∈ [0,1]}` — no free text, so the answer cannot carry an injection back; (3) `doc-sentinel review-merge` validates answers against the plan (ids, enums, ranges, plan hash) and re-aggregates; monotonic: semantic review can only add or raise findings, never remove or lower (L30 Q2 unanswered → safe default, stated to the user); (4) agents that cannot spawn subagents report the deterministic verdict and say semantic review did not run; (5) a file pasted as text in chat is already read by the orchestrator → the agent asks for the file path / `inbox/` instead.
- **S13 contract (parent, after T18 research L31).** Security does NOT rely on subagent tool restrictions (L31: not OS confinement; Codex children inherit the parent sandbox; Cursor `readonly` still allows shell; Grok `allowed-tools` does not restrict). Layers: (1) the orchestrator never receives document text: `--agent-summary` prints an orchestrator-safe JSON (verdict, exit, counts by severity/class/channel/adapter, adapters run/skipped/failed, output/report/review paths, review needed + batch list) with NO excerpts, matched text, filenames of embedded parts or metadata values; the full report goes only to `--report` (the orchestrator must not open it); (2) subagents get only bounded fragments, spotlighted by datamarking (whitespace replaced by a marker, per Microsoft "spotlighting", Hines et al. 2024) inside an explicit untrusted-data envelope; (3) answers are schema-only (`{plan_id, batch_id, results:[{task_id, label ∈ {injection, benign, unsure}, score ∈ [0,1]}]}`, no other keys, ≤ 64 KiB) and validated by the CLI, never interpreted by the orchestrator, which saves the subagent reply verbatim with its file-write tool (never through a shell command) to `<review-dir>/answers/<batch_id>.json`; (4) monotonic merge: semantic results only add findings or raise severity, never remove/lower; invalid or missing answers leave the deterministic verdict unchanged and are listed in `review_errors`; (5) per-agent reviewer definitions restrict tools where the platform supports it (Claude Code `tools: Read`; Gemini `tools: [read_file]`; Copilot `tools: [read]`; OpenCode permissions deny all but `read` on the review dir; Cursor/Grok reuse `.claude/agents`; Codex `.codex/agents/*.toml` with shell disabled where supported and a documented caveat; Antigravity: AGENTS.md generic flow), and AGENTS.md says: if the platform cannot run an isolated reviewer, skip semantic review and report the deterministic verdict.
  CLI surface: `doc-sentinel detect FILE [--report PATH] [--agent-summary] [--review-dir DIR]`; with `--review-dir` it writes `plan.json` (schema_version, plan_id = sha256 over input sha + batch contents, input_sha256, deterministic verdict, batches [{batch_id, file, task_ids, fragments}], parallel_ok, answer_schema, reviewer = "doc-sentinel-reviewer", limits) and `batches/<batch_id>.json` (plan_id, batch_id, untrusted-data notice, fragments [{task_id, channel, source (adapter/rule), hidden, text (datamarked, ≤ 600 chars)}]); no fragments → zero batches. Fragment selection: every revealed hidden/divergent text; every non-body channel with ≥ 8 letters (filename, metadata, comment, annotation, alt, hyperlink, embedded, form_field, tracked_change, html_hidden, image_ocr); body text only around deterministic findings (instruction-phrases, subtext-scan phrasing); dedupe by normalized text; ≤ 24 fragments per batch, ≤ 8 batches, overflow recorded as `truncated`. `doc-sentinel review-merge --review-dir DIR [--report PATH] [--agent-summary]` validates every `answers/*.json` against the plan and re-aggregates (adapter `agent-review`, confidence `model`; label injection with score ≥ 0.5 → finding; severity high (≥ 0.9 critical) for hidden/non-body channels, medium for visible body; `unsure` → info); exit codes as detect. Launchers map `--review-dir` to a read-write mount `/work/review` and pass `review-merge` through. Workspace convention: reports and review dirs under `reports/<stem>-<UTC timestamp>/` (git-ignored).

- **S14 — Sanitized copy (optional, inside detect).** User (L32): after a positive detection, optionally produce "ese mismo documento … quitando la inyección de prompt … y dejando lo que ve el usuario, en caso de que haya una diferencia entre lo que ve el usuario y lo que muestra realmente la extracción"; "solo se removería eso, no se modificaría nada más". Decisions (L33, L34): (a) prompt injections are removed even when VISIBLE; (b) EVERY hidden/divergent element is resolved toward what the user sees, injection or not (hidden runs/text removed; glyph↔ToUnicode divergence repaired so extraction equals the drawn glyph — the user's example: a hidden "=" that turns ">" into ">=" must disappear); exceptions only for format characters that change rendering legitimately (ZWJ in emoji sequences, ZWNJ/ZWJ in Arabic/Indic scripts); (c) nothing is ever added to the document (no notes, comments, metadata, marks); the report is separate and lists every removal/repair with location, technique, visibility (visible|hidden), reason and the removed text kept only in the report. CLI: `detect FILE --sanitize [-o OUT]` (default `<stem>.sanitized<suffix>`; same output/report safety guards as clean) and `doc-sentinel sanitize --review-dir DIR [-o OUT]` after review-merge so semantic findings are included. Self-checks before delivering the copy (else no NEW output — a pre-existing `--force-output` target is preserved untouched; the detect `verdict` is unchanged because it describes the document; `sanitize.status` = refused|unsupported with `refusal_reason`; exit code 2 when a requested sanitized copy was not delivered, otherwise detect's exit code; `nothing_to_do` keeps detect's exit code — decision L38): visible rendering identical page by page except where a VISIBLE injection was removed (those regions listed); extracted text = original extraction minus removed fragments; re-running detect on the copy finds none of the remediated findings; the copy opens (LibreOffice/pymupdf). Formats in scope first: DOCX, PDF, HTML, TXT/MD; others report "sanitize unsupported" without output.

- **S15 — PDF sanitize = faithful DOCX reconstruction.** User (L39): for PDFs, "genera una version parecida en word, lo mas fiel posible sin la parte de injection o maliciosa que no se veia". `detect --sanitize` / `sanitize` on a PDF writes `<stem>.sanitized.docx` (never edits the PDF). Built from the PDF's visible content only: text spans with font family, size, bold/italic/underline, visible colour, reading order, paragraphs, alignment estimate, page size/margins, page breaks, images (same size/order), tables (pymupdf find_tables), hyperlinks (visible ones), lists, repeated top/bottom lines as header/footer when consistent. Excluded (each listed in the separate report with page, bbox, technique, visibility, reason): invisible text (render mode 3 via pymupdf texttrace), text outside the visible box, text in OFF optional-content layers, spans matching hidden_text findings (white-on-background, tiny) by page + bbox overlap + text, and supplied injection spans (visible ones too, L33). Self-checks: DOCX opens (python-docx + LibreOffice conversion); normalized DOCX text == normalized visible PDF text minus exclusions; re-detect on the DOCX finds none of the removed items; per-page visual similarity (LibreOffice render of the DOCX vs PDF page) reported as a metric, not a gate ("parecida", L39). Glyph/ToUnicode divergence → refused (extraction would carry the lying text). Scanned/image-only PDFs: output keeps the page images, reports "no text layer" (no OCR text injected into the document).
- **S14 tracked changes rule (L40, confirmed by the user in L41):** "what the user sees" = the FINAL view: tracked deletions removed, tracked insertions kept (unwrapped); the DOCX render check compares the output against a final-view rendering of the original.
